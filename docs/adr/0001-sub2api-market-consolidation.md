# ADR 0001：闲猫产品形态与并仓决策

- **状态**：已接受（2026-10-20 定稿为闲猫专属仓）
- **日期**：2026-10-19
- **议题**：闲置 TOKEN 市场与网关/管理端如何同仓交付

## 背景

闲猫（IdleCat）需要：

- 一套管理端运营网关、账号、分组与市场供给；
- 一套 C 端完成市场 / 买家 / 卖家；
- 同一登录、同一端口，避免双控制台。

## 决策

1. **本仓库根目录即闲猫产品宿主**：`backend/` + `frontend/` + `market/`。
2. **产品形态：**
   - **管理端 = `frontend/` `/admin`**：运营控制台；侧栏「闲猫」为市场增量。
   - **C 端 = `market/web` `/`**：闲置 TOKEN 市场 / 买家 / 卖家。
   - **`/admin` 与 `/console`**：进入上述管理端；已登录则换发会话，不再二次登录。
3. **市场后端**以 `market/` 为主（Edge、挂单、质检、人民币账本等）。
4. **采用渐进交付**；资金域最后切生产。
5. **对外品牌统一为闲猫 / IdleCat**，不再以第三方社区项目名义发布。

## 后果

### 正向

- 运营只进一套管理端。
- C 端闲置 TOKEN 体验独立。
- 仓库即产品，GitHub 发布面清晰。

### 负向

- 与上游社区升级时需自行消化冲突（主题、导航、`market/`）。

## 配套约束

- 公网 www → `market/web`（C 端）；管理域 → `frontend/`。
- 模块地图见 [docs/dev/consolidation-module-map.md](../dev/consolidation-module-map.md)。
