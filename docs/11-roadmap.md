# 11 路线图与待定事项

## 1. 第一期里程碑

| 里程碑 | 内容 | 依赖 |
|---|---|---|
| M0 基础（**已完成**） | 仓库骨架、配置与加密、数据库迁移；sub2api 适配层（adminclient、userclient、replica、ops 出站表）；契约骨架与 s2a-compat 静态预检 | — |
| M1 卖家上架 | 上游与挂单模型；OAuth 与 Coding Plan 上架流程；代理分配；执行器与状态对账；默认分组与优先级段 | M0 |
| M2 买家与 Edge | 注册、充值（先接测试通道）、影子用户与内部 key、买家 Key；Edge（默认分组与卖家链、故障转移、熔断、跳过列表、配置分发）；市场列表 | M1 |
| M3 结算 | 用量入账、复式账本、按小时结算、冻结期、对账；提现申请与人工打款 | M2 |
| M4 质量检测 | 厂商检测策略与开关；探测执行与预算；题库与 IRT 标定；基线账号；SPRT 判定与归因；不调度与恢复复测；卖家测试报告与申诉；回收报价引擎 | M1 |
| M5 上线准备 | s2a-compat 结构比对与行为契约；运行时自检与安全模式；资金风控基础规则；监控告警；压测（含 sub2api 在大量分组下的调度开销） | M2–M4 |

M3 与 M4 可以并行。

**M0 交付内容**：配置加载（YAML + 环境变量）、AES-256-GCM 字段加密（支持密钥轮换）、本系统数据库迁移器；sub2api 适配层（`apiwire`、`adminclient`、`userclient`、`replica`、出站表 `ops` 与 `opshandlers`、运行时自检 `compatguard`）；契约文件与 6 条只读查询；`s2a-compat` 的 `check`（静态预检 + 临时库查询校验）与 `fingerprint`；`market-worker`（迁移、兼容自检、出站发送）与 `market-api`（健康检查、sub2api 集成状态）。单元测试、集成测试（真实 PostgreSQL + sub2api 0.2.14 全部迁移）与冒烟测试（真实运行的 sub2api 0.2.14）。

**M0 未覆盖**：Admin API 的实测需要管理员先在 sub2api 完成合规确认；s2a-compat 的完整结构比对（启动 sub2api 镜像）与行为契约阶段放在 M5；Edge 在 M2 实现。

## 2. 后续阶段

**第二期**

- Edge 观测扩展：推理 token、工具调用合规率、截断与拒答率，作为被动降智信号。
- Edge 支持图片、视频、异步任务接口（需要任务与跳的映射）。
- 调度策略：探索-利用（新上游保底流量）、公平分配、按目标份额的闭环控制。
- 可售时段（卖家只在指定时段出售）。
- 买家等级折扣（sub2api 分组的用户专属倍率）。
- 提现自动审核、代付通道自动化。

**第三期**

- 官方 API Key、按量付费 key、第三方中转站接入。
- 卖家接入网关：中转站的真实流量 token 审计、凭证不出平台、循环套利识别。
- 同一上游按模型分别定价（仅 API Key 类可拆账号实现）。
- 动态定价、按供需调整回收报价。
- 抽佣按卖家等级分档。

## 3. 待定事项

| # | 事项 | 影响 |
|---|---|---|
| 1 | 支付与代付通道，以及给个人打款的合规方案（代付、税务） | 充值、提现 |

| 6 | 代理来源（住宅 / 机房、地区）与每个上游独占还是共享 | 封号风险、降智归因 |
| 7 | 买家隐私：各厂商卖家能否在自己账号后台看到买家的请求内容，需要逐一确认，并在买家侧告知 | 合规、买家信任 |
| 8 | 用户协议与卖家协议：封号责任、降智规则、隐私告知、违约处理 | 合规、纠纷 |

已定：计价币种与汇率，统一按 1:1 结算（决策 D16）；计费以 sub2api 实际产生的费用为准，买家中途断开时 sub2api 产生了费用就计费（决策 D17）。

## 4. 主要风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 违反厂商服务条款 | 各厂商的订阅与 Coding Plan 都限个人使用，转卖会导致封号 | 固定代理、TLS 指纹、保守的并发与限流、窗口留余量；协议中明确封号责任 |
| sub2api 合规承诺 | sub2api 要求管理员确认《部署与运营合规承诺》（`docs/legal/admin-compliance.zh.md`）后才能使用管理接口。其中第四条要求确认方遵守上游服务条款与转售限制，且不在缺乏授权、资质、备案的情况下提供"账号额度分发、共享订阅、付费调用"等服务，与本平台的业务直接相关 | 由运营方自行评估并决定是否确认；本系统不代为确认 |
| 套现与洗钱 | 现金提现 + 指定卖家，容易被利用 | 见 [08](08-billing.md) 第 9 节 |
| sub2api 升级不兼容 | 本系统依赖其 API、表结构和行为 | s2a-compat 闸门 + 运行时自检 |
| Edge 成为单点 | 唯一在请求链路上的新组件 | 多实例、无状态、热路径不依赖数据库 |
| 降智误判 | 冤枉卖家导致纠纷 | 基线对照、统计检验、归因、申诉复测 |
