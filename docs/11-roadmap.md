**M0 交付内容**：配置加载（YAML + 环境变量）、AES-256-GCM 字段加密（支持密钥轮换）、本系统数据库迁移器；sub2api 适配层（`apiwire`、`adminclient`、`userclient`、`replica`、出站表 `ops` 与 `opshandlers`、运行时自检 `compatguard`）；契约文件与只读查询；`s2a-compat` 的 `check` 与 `fingerprint`。

**M1–M5 交付内容**

- **上架**（`internal/listing`）：五家 OAuth（Claude oauth / setup-token、ChatGPT、Gemini Google One / Code Assist、Antigravity、Grok）与四家 Coding Plan（Kimi、智谱国内站 / 国际站 / 团队版、MiniMax 国内站 / 国际站、OpenCode Go）；专用代理分配；官方账号去重（盲索引）；OpenAI / Antigravity 隐私设置；Coding Plan 订阅校验；重新授权（同一官方账号，只换凭证）；寄售与回收两种挂单、改价冷却、报价与续报价；删除上游的分步下线。
- **调度**（`internal/scheduling`）：纯函数规划器（回收段 1–19 按等级、寄售段 50–79 按 0.05 价格档）、最小差异执行器（移出面向买家分组的操作优先、每轮改动预算）、待发送操作去重、账号健康同步、缺失账号与孤儿账号检测；Redis 通知即时重算。
- **买家与 Edge**（`internal/buyer`、`internal/edge`）：影子用户（密码与令牌加密、刷新失败再登录）、按跳开通内部 key（`custom_key` 幂等）、路由校验、配置发布与跳过列表；Edge 的鉴权、IP 白名单（受信任代理规则）、无效 Key 限速、首字节前故障转移、首字节截止时间、熔断、WebSocket 握手故障转移、流式透传、尝试日志（批量写库 + 本地暂存）。
- **结算**（`internal/billing`）：两分钟安全延迟 + 重叠重扫的用量入账、归属解析（卖家 / 挂单 / 买家 / 渠道 / 探测）、复式账本（延迟约束保证借贷平衡）、上游 × 小时 × 渠道结算行、冻结期解冻、充值（出站幂等加余额）、退款状态机（锁 Key → 扣余额 → 记账 → 打款）、提现（实名、可提现锁、自动审核阈值、风险转人工）、人工调账、R1–R4 逐次对账与余额恒等式核对、Key 花费限额。
- **质量检测**（`internal/quality`）：策略（厂商级 / 接入方式级 / 单上游覆盖）、题库与判分器、四种协议的探测客户端、同批次基线对照、SPRT 序贯判定与自适应追加题量、归因（官方全局 / 代理 / 账号）、降智不调度与退避恢复复测、定级与回收报价、脱敏报告、趋势、手动复测、申诉复测、被动信号、探测余额保障。
- **控制面**（`internal/httpapi`）：[10](10-api.md) 列出的全部接口，管理员操作审计。
- **上线准备**：worker 选主（advisory lock）与管理端口指标；控制面同步写入的兼容门控；安全模式下暂停入账、对账、质量检测；`s2a-compat check --target-version` 与 `s2a-compat routes`；`scripts/upgrade-sub2api.sh`。
- **在线支付**（`internal/payment`）：支付宝 OpenAPI 客户端（RSA2，公钥 / 公钥证书两种模式；电脑网站支付、当面付预下单、查单、关单、退款、退款查询、异步通知验签）、微信支付 APIv3 客户端（请求签名、应答验签、微信支付公钥或自动下载平台证书、Native 下单、查单、关单、退款、通知验签防重放与解密）；充值单状态机（通知与查单入账、金额校验、超时关单、取消后付款照常入账）、退款打款拆分与原路退回（`internal/billing`）。
- **第三方检测**（`internal/quality/thirdparty`）：检测站接口与登记表、BazaarLink 客户端（提交、轮询、限流、结论归类与脱敏摘要）；质量引擎中的第三方阶段（排队、频率控制、Edge 临时令牌、轮询、超时、撤销令牌、结论合并）。
- **测试**：单元测试；集成测试在 sub2api 0.2.14 真实表结构上运行 sub2api 替身（`internal/testutil/fakesub2api`），端到端覆盖上架、调度收敛、Edge 故障转移、入账、对账、退款、提现、限额、风控、质量检测、申诉、重新授权与全部接口；支付与第三方检测分别用按真实协议签名验签的替身（`internal/testutil/fakepay`、`internal/testutil/fakebazaar`）端到端覆盖。

**未覆盖 / 需要运营方完成**

- **镜像构建未在本机验证**：开发机无法访问 Docker Hub，`Dockerfile` 的各构建步骤已在本机分别验证（前端 `pnpm install --frozen-lockfile && pnpm build`、`CGO_ENABLED=0 go build`），完整镜像需要在能拉取基础镜像的环境构建一次。
- **前端多语言**：第一期界面只有中文。
- **真实 sub2api 的 Admin API 联调**：需要运营方管理员在 sub2api 完成《部署与运营合规承诺》确认（见第 4 节风险）。本系统不代为确认。确认后在预发环境跑一遍端到端流程与 `s2a-compat routes`。
- **真实厂商授权**：各厂商的 OAuth 换取与凭证字段按 sub2api 0.2.14 前端的调用方式实现，需要用真实账号逐一验证。
- **支付宝 / 微信支付真实商户联调**：协议按官方文档实现，并用按同一协议签名验签的替身做了端到端测试；上线前需要用运营方的商户号（可先用支付宝沙箱）验证下单、通知、查单、关单与退款各一次，特别是公钥证书模式的证书序列号。
- **提现代付**：提现仍为人工打款（支付宝转账、微信商家转账需要单独开通产品与资质，见待定事项第 1 项）。
- **BazaarLink 真实联调**：已用真实接口确认提交、轮询与响应结构；对平台上游的完整检测需要 Edge 有公网 https 地址后在预发环境执行。每次检测约 90 个请求，会消耗卖家订阅窗口，建议只在上架检测、管理员检测与申诉复测中启用。
- **题库内容与 IRT 标定**：内置约 20 道通用题作为起点；需要运营方准备私有题库，并用基线账号与已知降智样本标定难度和区分度。
- **压测**：Edge 吞吐、sub2api 在大量分组下的调度开销，需要在预发环境执行。
- **监控告警**：已提供 `/debug/vars` 指标与健康检查，告警规则需要接入运营方的监控系统。

## 2. 后续阶段

**第二期**

- Edge 观测扩展：推理 token、工具调用合规率、截断与拒答率，作为被动降智信号。
- Edge 支持图片、视频、异步任务接口（需要任务与跳的映射）。
- 调度策略：探索-利用（新上游保底流量）、公平分配、按目标份额的闭环控制。
- 可售时段（卖家只在指定时段出售）。
- 买家等级折扣（sub2api 分组的用户专属倍率）。
- 提现自动审核、代付通道自动化。

**第三期**

- 官方 API Key、按量付费 key、第三方中转站接入。
- 卖家接入网关：中转站的真实流量 token 审计、凭证不出平台、循环套利识别。
- 同一上游按模型分别定价（仅 API Key 类可拆账号实现）。
- 动态定价、按供需调整回收报价。
- 抽佣按卖家等级分档。

## 4. 主要风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 违反厂商服务条款 | 各厂商的订阅与 Coding Plan 都限个人使用，转卖会导致封号 | 固定代理、TLS 指纹、保守的并发与限流、窗口留余量；协议中明确封号责任 |
| sub2api 合规承诺 | sub2api 要求管理员确认《部署与运营合规承诺》（`docs/legal/admin-compliance.zh.md`）后才能使用管理接口。其中第四条要求确认方遵守上游服务条款与转售限制，且不在缺乏授权、资质、备案的情况下提供"账号额度分发、共享订阅、付费调用"等服务，与本平台的业务直接相关 | 由运营方自行评估并决定是否确认；本系统不代为确认 |
| 套现与洗钱 | 现金提现 + 指定卖家，容易被利用 | 见 [08](08-billing.md) 第 9 节 |
| sub2api 升级不兼容 | 本系统依赖其 API、表结构和行为 | s2a-compat 闸门 + 运行时自检 |
| Edge 成为单点 | 唯一在请求链路上的新组件 | 多实例、无状态、热路径不依赖数据库 |
| 降智误判 | 冤枉卖家导致纠纷 | 基线对照、统计检验、归因、申诉复测 |
