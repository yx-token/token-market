# 01 总览

## 1. 背景与目标

很多人买了 Claude Max、ChatGPT Pro、Kimi Coding Plan 这类订阅，但用不完，额度到点重置就作废。本平台让卖家把闲置额度挂出来变现，买家以低于官方 API 的价格购买。

平台要解决四件事：

1. **供给接入**：卖家只做授权，不交密码；平台托管凭证、代理和调度。
2. **质量保证**：检测可用性、性能和降智，质量差的上游自动停止调度。
3. **流量分配**：默认分组优先消化平台回收的库存，再用低价寄售补充；买家也可以自己指定卖家。
4. **资金结算**：买家充值消费，卖家按用量结算并提现，平台赚取差价或抽佣。

## 2. 第一期范围

**包含**

- 上游类型：官方 OAuth 订阅账号（Claude、ChatGPT/Codex、Gemini、Antigravity、Grok）和国产订阅（Kimi / 智谱 GLM / MiniMax 的 Coding Plan、OpenCode Go）。
- 两种挂单模式：寄售（卖家自定倍率 + 固定抽佣）、平台回收（平台报价，按用量结算）。
- 买家：注册、充值、创建 Key、走默认分组或指定最多 5 跳的卖家链。
- 质量检测：上架检测、定时检测、降智判定、厂商级检测开关、卖家可查看测试报告。
- 结算：按用量结算、冻结期、卖家现金提现。
- sub2api 兼容闸门工具 s2a-compat。

**不包含（后续再做）**

- 官方 API Key、按量付费的 key（如 DeepSeek）、第三方中转站。
- 卖家接入网关（用于中转站的真实流量审计）。
- 同一账号按模型分别定价。
- 动态定价、探索-利用等高级调度策略。

## 3. 角色

| 角色 | 说明 |
|---|---|
| 卖家 | 授权上游、选择挂单模式、设置自留比例和倍率、查看测试报告和收益、提现。提现前必须实名 |
| 买家 | 充值、创建 Key、浏览市场、指定卖家、查看用量和账单 |
| 管理员 | 配置检测策略、题库、基线账号、默认分组价格、抽佣，审核提现和申诉 |

同一个平台用户可以既是买家又是卖家。

## 4. 术语

| 术语 | 含义 |
|---|---|
| 上游（Upstream） | 卖家授权的一个订阅账号或一个 Coding Plan key，对应 sub2api 里的一个账号（1:1） |
| 挂单（Listing） | 上游的一次商业挂出，包含模式、倍率、状态。一个上游同一时间最多一个有效挂单 |
| 寄售（Consignment） | 卖家自定倍率 m_s 的挂单，可以在市场上被买家指定 |
| 回收（Buyback） | 平台按质量报价 m_b 的挂单，只进入默认分组 |
| 官方价 | sub2api 内置价目表中的模型价格（美元国际版标价），即 usage_logs 的 `total_cost` |
| 倍率 | 相对官方价的系数，口径与 sub2api 的 `rate_multiplier` 一致 |
| 抽佣率 c | 全局固定值。寄售挂单的买家价 p = m_s × (1 + c) |
| 默认分组（Pool） | 平台按模型族提供的分组，售价倍率为 D |
| 卖家链（Chain） | 买家 Key 上配置的有序卖家列表，最多 5 跳，最后一跳可以是默认分组 |
| 影子用户 | 每个买家在 sub2api 里对应的用户，买家不可见 |
| 内部 Key | 影子用户名下的 sub2api key，每个"买家 Key × sub2api 分组"一把 |
| 探测（Probe） | 平台主动发给上游的测试请求 |
| 基线账号 | 平台自备的干净官方账号，用于降智判定的对照 |
| 不调度 | 把上游从所有买家可用的分组中移出，只保留在探测分组 |

| D19 | 支付接入支付宝（电脑网站支付、当面付）与微信支付（Native 扫码），保留人工确认作为兜底；到账只认验签通过的异步通知或主动查单结果；余额退款优先原路退回，不足部分人工打款 | 2026-10-08 |

| D21 | 支付配置（通知地址、支付宝应用、微信支付商户及其密钥）改为在管理后台站内动态配置，密钥加密存库，不再使用配置文件与环境变量 | 2026-10-09 |
