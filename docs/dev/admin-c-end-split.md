# 管理端 / C 端分工与功能对照

> 依据 ADR 0001（2026-10-19 再修订）。宿主：`../idlicat`。

## 终态分工

| 面 | 落点 | 说明 |
|---|---|---|
| **管理端** | 社区 `frontend/` `/engine/admin/...` | sub2api 原壳；闲猫运营在侧栏「闲猫市场」 |
| **C 端** | `market/web` `/` | 闲置 TOKEN：市场 / 买家 / 卖家 |
| `/admin`、`/console` | 跳转 `/engine/admin/dashboard` | 书签兼容；已登录则先换发会话 |

## 实施顺序（已纠正）

1. **管理端用 sub2api 原壳**，闲猫能力作为增量菜单
2. **C 端保留** `market/web` 市场/买家/卖家
3. 闲猫市场请求使用 C 端 `tm_token`，不跟引擎会话混用
4. `/admin`、`/console` 只做跳转，不再另开闲猫 Console

## 闲猫管理端能力清单（应对齐进 sub2api 壳）

### 值班
- 概览
- 充值 / 退款 / 提现
- 质量与申诉
- 风控
- 计费异常

### 闲置 TOKEN（供给）
- 上游
- 默认分组（池）
- 厂商
- 代理

### 检测
- 检测策略
- 质检项
- 检测记录
- 第三方检测
- 题库与基线

### 运营
- 热搜与筛选
- 市场分类
- 货架开关

### 治理
- 用户与实名
- 支付配置
- 系统设置
- 系统更新
- 审计日志

### 组织
- 组织架构 / 角色 / 员工授权

## sub2api 管理端已有（保留，改皮肤）

账号、分组、渠道、订阅、代理、公告、风控/审核、兑换码、推广、订单支付、用量、审计、设置等——**留在同一壳内**，菜单按闲猫信息架构重排，不另开第二后台。

## C 端闲置 TOKEN（`market/web`，非管理端）

- 市场首页 / 挂单详情 / 品牌墙 / 热搜筛选
- 买家：Key、钱包、商家清单、活动包、用量、账单、资料
- 卖家：上架、上游、代理、挂单、收益、活动包
- 登录注册（C 端）

## 与上一轮实现的关系

`frontend/src/market-admin/` 双登录拼装页 = **错误中间态**（社区皮 + 外挂市场页）。后续应收敛为：闲猫风 sub2api 壳内的正式运营页，而不是长期保留独立登录墙。
