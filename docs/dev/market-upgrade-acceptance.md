用户确认：活动包以人民币定价、美元表示额度，按店铺实际计费价扣额度。现有按量业务保持 D16 的平台余额单位口径；活动包换算配置必须明确并保留购买时快照。

## 验收标准

1. 市场商品可加入持久化商家清单；按商家去重。Key 选择范围仅为清单内商家，顺序保存后重新打开仍一致；服务端拒绝清单外新增选择。既有 Key 不因升级失效。
2. 用量入账同时体现买家支出、卖家冻结收益；冻结期后台可修改，缺省为 24 小时。未满期限不能解冻，重复运行或并发不能重复付钱。
3. 卖家账号、接入、挂单、上游详情、收益、用量和代理页面均可用，表单有清楚的状态与反馈，手机宽度不遮挡关键操作。
4. 有效授权上游可跳过质检后发布；不能绕过无效凭证、模型白名单与管理员隔离。买家清楚看到未检测，gpt-6-astra 单独展示降智结果；无检测结果不展示通过。
5. 卖家可发布独立店铺活动包，分别输入人民币售价和美元额度，设置全部店铺或指定厂商/模型；仅同一卖家且符合范围的用量可抵扣。购买快照不随活动修改而变化。
6. 一笔用量跨过额度余额时，仅包内部分抵扣，差额扣平台余额；重放不重复消费，其他店铺不能使用或套现。退款、旧额度包、对账与账本平衡不回归。
7. 全部 Go 单测、前端测试、构建，以及使用真实 PostgreSQL/Redis 和替身上游的相关集成测试通过。浏览器以 ego-browser 验证真实页面。

## 独立复核发现与修复

- GLM 5.3 max 对需求 1/4 的独立复核未发现 P0/P1，发现旧在线额度包在支付期间移除商家/挂单失效的 P2：履约失败后库存未释放，前端无限等待。最终实现尊重买家的移除选择，不自动加回商家；仅未签包的 pending checkout 可转 failed 并释放一次库存，已到账资金保留普通余额，不重复入账或退款。checkout 与包在同一事务提交 fulfilled，避免把处理中订单提前显示为成功；充值接口按订单归属返回可选履约状态。
- 收尾进一步覆盖写包与延迟提交失败：签包失败时清理该次已创建、无包关联的 Key，并撤销 Edge 路由。Key 清理独立于是否先抢到失败状态，checkout 行锁串行协调收尾与成功履约；已签包 Key 与库存不受影响。新增真实 PG/Redis 专项确定性覆盖两个 worker 先后收尾，e2e 覆盖商家移除、挂单暂停、写入失败、提交失败、正常履约、库存重试、资金保留与越权读取。
- P3 的 Key 主列表路由状态提示已补齐，前端测试和浏览器均通过。
- GLM 5.3 max 已完成最终只读复核，确认并发失败收尾修复正确，最终 `failPendingPackCheckout`、`fulfillOne`、`getRecharge` 与前端失败停等/跳过标记无 P0/P1/P2 阻塞项。

## 运行边界

- 用量保留现有约 2 分钟安全入账延迟；不能将跨进程余额与账本描述为即时原子一致。
- 冻结期默认 24 小时，按小时桶结束后起算，保守额外等待不足 1 小时，再加 worker 轮询时间。
- 店铺活动抵扣适用于可确定本店的普通 HTTP 计费 POST。默认池、WebSocket、模型列表、countTokens 沿既有余额路径；旧固定额度包及其专用 Key 独立存在。
- 同一个活动包的请求在完整 HTTP/SSE 响应期间串行，持有数据库连接。需按实际 SSE 并发设置数据库连接池；远端异步用量/余额缓存仍有既有延迟边界。
- 远端购买/开通/退款操作进入 dead 时，保留资金和状态等待既有 outbox 运维重试；现金补差不足在充值后自动重试原幂等操作。新活动钱包显式零余额创建，早期试验钱包若已有来源不明赠金不会自动清零。
