# 人民币账本 vs sub2api `users.balance`

> 阶段 6 前置设计。同实例可共库，**禁止把两套余额当成同一个字段。**

## 两套余额

| 余额 | 落点 | 单位与含义 | 谁读写 |
|---|---|---|---|
| 市场人民币账本 | 市场库 `ledger_*` / 买家钱包视图 `ledger_cash`、充值退款提现 | 人民币（CNY），平台对买家/卖家的应收应付 | `billing` / `payment`。引擎进程经 `enginehost` 调用同一套代码，不另写 SQL |
| 引擎美元余额 | 引擎库 `users.balance`（及冻结余额） | 网关计费用的额度，通常按官方价 × 倍率扣减 | sub2api 扣费路径；影子用户 / 活动钱包隔离用户 |

## 硬边界

1. **不要**用 `UPDATE users SET balance = …` 去“同步”市场钱包，也不要拿 `ledger_cash` 当 Edge 鉴权余额。
2. 买家充值到账：先记人民币账本；若需要引擎侧额度，经出站队列 / Admin 调账写**影子用户**余额，且金额换算走显式汇率（见 `credit_usd_to_balance_rate`），不得隐式等同。
3. 卖家收益、提现、退款、申诉改判：只动市场账本与支付商户；不回写社区用户门户余额。
4. 店铺活动包：引擎侧是独立 `credit_pack` 影子用户 + 预付负债；包内抵扣与现金补差规则以 `docs/dev/billing-validation.md` 专项为准。
5. 确认充值、退款打款、提现审核、申诉裁决已由引擎进程调用原 `billing.Funds` / `quality.Engine`。入账仍只写市场库，并按原逻辑经出站队列给影子用户加引擎额度。

## 尚未收口

1. 充值 / 退款 / 提现 / 活动包 integration + 支付替身在宿主 go.work 下尚未重跑。
2. 恒等式失败时回滚的是这次写迁移，保留市场账本代码路径，不要改成直接改 `users.balance`。

## 验收口令

- 任意资金恒等式失败 → 回滚写迁移，保留 market-api 写路径。
- Edge / 社区扣费路径未被改写；failover 与计费回归独立验收。
